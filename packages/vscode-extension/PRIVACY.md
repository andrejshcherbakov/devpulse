# Privacy Policy

**Last updated:** November 7, 2026

DevPulse is a self-hosted VS Code activity tracker. The extension sends
workflow metadata to the backend selected by the user. The backend operator is
the data controller and is responsible for access, retention, deletion, and
legal compliance for the deployed service.

No activity events are buffered or transmitted until an Extension API key and
a valid API URL are configured. DevPulse also requires an enabled master
switch, a trusted workspace, and the VS Code telemetry setting to be enabled.

## Data sent to the configured backend

All events can include a client timestamp, Git branch, sanitized Git remote
URL, VS Code-generated machine ID, and VS Code session ID.

| Event                     | Data                                                              |
| ------------------------- | ----------------------------------------------------------------- |
| `heartbeat`               | Relative active file path when enabled, language                  |
| `file_save`               | Relative file path when enabled, language                         |
| `file_switch`             | Relative file path when enabled, language                         |
| `idle_start` / `idle_end` | Activity boundary and duration                                    |
| `session_end`             | Session boundary and idle duration                                |
| `terminal_command`        | Sanitized command, relative cwd, exit code, duration when enabled |
| `task_run`                | VS Code task name, source, exit code, duration                    |
| `git_commit`              | Hash, optional message, diff totals, optional changed-file paths  |
| `ai_interaction`          | Detected tool name and a flag that the interaction is an estimate |

The backend can derive sessions, active and idle time, language usage, file
time, command outcomes, focus estimates, and AI-assisted activity estimates
from these events.

### Identifiers and network metadata

`machineId` and `sessionId` are identifiers generated by VS Code. They are not
hardware serial numbers, but they are persistent or session-level
pseudonymous identifiers. The extension does not add the user's name or email
to event payloads. Like any network service, the configured backend can observe
the request IP address and standard transport metadata.

### Git metadata

Branches, remote URLs, commit messages, and file names can contain company,
customer, ticket, or personal information. HTTP(S) credentials are removed
from remote URLs and URL query/fragment data is not needed for analytics.
Commit-message and file-path transmission can be disabled independently.

### Terminal metadata

Terminal output is never collected. Command text is sanitized on a
best-effort basis before transmission. Known URL credentials, bearer tokens,
and common secret flags such as `--password`, `--token`, and `--api-key` are
masked. No sanitizer can recognize every secret format, so users working with
sensitive commands should disable `devpulse.sendTerminalCommands`.

The terminal working directory is sent only when it can be represented as a
path relative to the active workspace. Absolute terminal paths are discarded.

### AI-assistance detection

When enabled, DevPulse checks text-change metadata locally to identify a large
multiline insertion while a known AI coding tool is installed. It does not
retain or transmit the inserted text. Only the detected tool name and an
`estimated` marker are sent. Snippets, clipboard paste, formatters, or other
tools can produce false positives.

## Data not sent by the extension

- complete source-code contents;
- text inserted into the editor;
- individual keystrokes;
- terminal output;
- clipboard or screen contents;
- absolute editor file paths;
- absolute terminal working directories;
- the API key inside telemetry payloads.

## AI-generated worklogs

Normal telemetry ingestion does not contact an AI provider. When a user
explicitly generates a worklog, the backend may send the configured AI
provider a bounded set of daily facts: active time, focus estimate, project and
branch names, language percentages, up to five relative hot-file paths,
aggregated terminal outcomes, commit messages when enabled, and the
AI-assisted percentage. Source-code and terminal-output contents are excluded.

The backend operator chooses the AI provider and is responsible for explaining
that provider's processing and retention terms.

## Storage and security

- The API key is stored with VS Code SecretStorage, backed by the operating
  system credential store where available.
- Remote API and dashboard endpoints must use HTTPS. Plain HTTP is permitted
  only for loopback development addresses.
- Up to 500 unsent events can be stored in VS Code global storage while the
  backend is unavailable.
- **DevPulse: Clear API Key** removes the key and the locally buffered events.
- DevPulse output logs remain local unless the user explicitly shares them.
  Logs can contain workspace names, branch names, sanitized commands, and
  operational errors.

## User controls

| Setting                         | Effect                                              |
| ------------------------------- | --------------------------------------------------- |
| `devpulse.enabled`              | Master tracking switch                              |
| `devpulse.sendFilePaths`        | Controls relative file paths and changed-file lists |
| `devpulse.sendTerminalCommands` | Controls terminal-command events                    |
| `devpulse.sendCommitMessages`   | Controls commit-message text                        |
| `devpulse.detectAiAssistance`   | Controls local AI-insertion detection and AI events |

Additional controls:

- Workspace Trust blocks tracking in untrusted workspaces.
- The VS Code telemetry toggle is always respected.
- Pause/Resume persists across VS Code restarts.
- Clearing the API key stops tracking and clears buffered events.
- Disabling a setting affects future events; it does not delete data already
  uploaded to a backend.

## Retention and deletion

The extension does not define server-side retention. Retention and deletion
are controlled by the operator of the URL configured in `devpulse.apiUrl`.
Users should contact that operator for exported or deleted server data. For a
self-hosted deployment, the user or organization running the deployment is the
operator.

Before uninstalling, run **DevPulse: Clear API Key** if locally buffered events
should be removed immediately. Uninstalling stops the extension; VS Code
controls cleanup of extension storage.

## Changes and contact
